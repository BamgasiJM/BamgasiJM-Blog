# 개인 기술 블로그 가능성 검토

확인일: 2026-11-08 (한국 시간). 이 문서는 서비스 구현 전 기본 설계다. 현재 저장소에는 소개 페이지와 로컬 Markdown 파일 탐색 API를 포함한 디자인 초안이 있으며 실행 방법은 루트 `README.md`에 기록했다. 실제 Next.js 앱·DB 연동은 구현 전이다.

## 결론

한 명이 작성하고 방문자는 읽기만 하는 기술 블로그는 무료 서비스로 충분히 시작할 수 있다. Markdown, 수식, 코드, 이미지, 시리즈 수동 정렬은 모두 일반적인 웹 기술로 구현 가능하다. 핵심 난점은 편집기 자체보다 초안 보호, 발행 버전 분리, 정렬 무결성, 이미지 관리와 복구다.

기본안은 **Next.js + Vercel Hobby + Supabase Free**다. 브라우저에서 글을 작성하는 관리 화면과 SQL 기반 순서 관리에 적합하며, 인증·DB·파일 저장소를 하나의 서비스로 묶어 운영 부담을 줄인다. 방문자에게 공개되는 개인·비상업 블로그를 가정한다. 비공개 개인 지식 저장소나 광고·유료 콘텐츠 운영이 목적이라면 접근 정책 또는 호스팅 선택을 다시 검토한다.

## 선택지 비교

| 구성 | 장점 | 제약과 적합성 |
| --- | --- | --- |
| Next.js + Vercel + Supabase | 관리자 UI, 인증, 관계형 데이터, 이미지 저장 구현이 직접적 | 무료 DB 중지·용량 제한, Vercel 비상업 조건. 현재 기본안 |
| 정적 사이트 + Git Markdown | 원문 버전 관리와 정적 페이지 배포에 유리 | 브라우저 편집·업로드·순서 저장에는 별도 CMS/Git 연동 필요. DB 기반 관리 요구와 거리가 있음 |
| Cloudflare Workers + D1 + 별도 이미지 저장소 | SQL과 서버 기능을 한 플랫폼 중심으로 구성 가능 | 인증·파일 저장 설계 및 프레임워크 어댑터 검토 필요. 이번 검토에서 무료 한도와 조건은 확인하지 않았으며 대안 후보로만 취급 |

외부 CMS나 서버리스 PostgreSQL을 조합할 수도 있지만, 이 프로젝트에서는 처음부터 여러 제공업체를 연결할 이점이 크지 않다.

## 실제 확인한 무료 플랜 제약

| 서비스 | 공식 문서에서 확인한 사항 | 설계에 미치는 영향 |
| --- | --- | --- |
| Vercel Hobby | 무료, 개인·비상업 용도로 제한. 사용 한도를 넘으면 기능을 다시 쓸 수 있을 때까지 대기해야 할 수 있음 | 상업화 전 요금제·호스팅 재검토. 무료로 무제한 트래픽을 보장하지 않음 |
| Supabase Free DB | 프로젝트당 DB 500 MB, 1주일 비활성 시 중지, 활성 프로젝트 최대 2개 | 개인 텍스트 블로그로 시작하기에는 적합. 낮은 방문량에서도 중지 가능하므로 복원 절차 필요 |
| Supabase Free Storage | 파일 저장 1 GB, egress 5 GB, cached egress 5 GB. 이미지 변환 기능 미포함 | 이미지 크기·전송량 관리가 우선. 두 egress 할당량을 임의의 10 GB 통합 한도로 계산하지 않음 |
| Supabase Free 백업 | 자동 백업 미포함. 무료 프로젝트는 CLI를 통한 정기 내보내기와 외부 보관 권장 | 자체 백업 절차 필요. DB 백업은 Storage의 이미지 파일을 포함하지 않음 |

예를 들어 이미지가 평균 200 KB이면 이미지 1,000장은 약 200 MB다. 한 페이지가 이미지 1 MB를 전송하고 그 페이지를 5,000번 읽으면 약 5 GB다. 이는 단순 용량 예시이며 캐시 적중, 실제 서비스 과금 분류, 다른 요청량에 따라 달라진다. 텍스트보다 이미지가 먼저 무료 한도를 압박할 가능성이 높다.

커스텀 도메인은 별도 구매 비용이 들 수 있으므로 초기에는 제공업체 기본 주소를 사용한다. 무료 서비스의 정책과 가용성이 영구적으로 유지된다고 가정하지 않는다. 기본 스택은 광고나 수익화가 없는 경우를 전제로 선택했다.

## 권장 기능 범위

MVP는 소유자 로그인, 좌우 Markdown 편집·미리보기와 양방향 스크롤 동기화, 수식·코드·이미지, 초안·발행·발행 취소, 폴더·글 트리, 시리즈·태그·수동 정렬, 공개 글·목차·이전/다음 이동까지다. 출시 전에 SEO, 모바일·키보드 접근성, 백업·복원까지 완료한다. 댓글, 방문자 가입, 실시간 협업, 코드 실행, 자체 통계, 전문 검색과 예약 발행은 초기 범위에 넣지 않는다.

Google Drive의 JPG·PNG·GIF는 선택 후 블로그 Storage로 복사하고, MP4·PDF는 공개 가능한 Drive 미리보기와 원본 링크를 제공한다. 가져온 이미지는 원본과 자동 동기화하지 않으며 Drive가 이미지 CDN이나 영구 가용성을 제공한다고 가정하지 않는다. 폴더 트리는 시리즈와 독립적으로 관리하고 공개 트리에는 발행 글과 그 상위 폴더만 표시한다. 구체적인 권한과 실패 처리 기준은 `AGENTS.md`를 따른다.

순서는 홈 글 순서, 시리즈 목록 순서, 시리즈 내부 글 순서를 별도로 저장한다. 최신순과 수동순은 혼합하지 않고 독립된 보기로 제공한다. 기본 소속은 글당 시리즈 하나이며 드래그 외에 키보드 이동도 지원한다.

발행된 글을 수정할 때는 편집 중 내용과 공개 스냅샷을 분리한다. 초안 저장이 즉시 공개 수정으로 이어지지 않게 하며, 한 명만 사용하더라도 다중 탭 저장 충돌은 처리한다. 초안 이미지는 공개 bucket에 넣지 않는다.

## 구현 전에 알아둘 운영 결정

- 현재 단계에서는 계정을 만들거나 배포하지 않는다. 실제 구현의 로컬 검증을 마친 뒤 배포에 필요한 계정·환경변수와 절차를 구체화한다.
- 무료 DB 중지 시 새 조회나 관리자 저장이 실패할 수 있다. 기존 페이지 캐시만으로 지속적인 사이트 가용성을 보장할 수 없다.
- 항상 읽을 수 있는 정적 보관본이 최우선 요구가 되면, 발행 때 정적 HTML을 생성하는 구조를 추가 검토한다. 이는 현재 기본 구현에 포함하지 않는다.
- 처음에는 명시적인 백업 실행 절차로 시작하고 사용 빈도에 맞춰 자동화한다. DB·Markdown·이미지를 외부에 보관하고 복원 테스트를 해야 백업이 완료된 것이다.
- 구현 단계와 검증 조건은 루트 `AGENTS.md`를 기준으로 삼는다. 세부 라이브러리 버전과 제공업체 한도는 설치·배포 시 다시 확인한다.

## 공식 근거

- [Vercel Hobby](https://vercel.com/docs/plans/hobby): 개인·비상업 제한 및 한도 초과 처리.
- [Supabase Pricing](https://supabase.com/pricing): 무료 DB·Storage·전송량·중지 정책·자동 백업 미포함.
- [Supabase Database Backups](https://supabase.com/docs/guides/platform/backups): 무료 프로젝트 내보내기 권고, Storage 객체가 DB 백업에서 제외된다는 설명.

위 문서는 확인일에 직접 조회했다. 제품 한도는 문서 작성 시점의 정보이며 계약상 영구 보장이 아니다.
